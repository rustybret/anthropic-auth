## What's fixed

- **Setup on Windows.** `bunx @cortexkit/opencode-anthropic-auth@2.0.1 setup` now finds OpenCode, Pi and the Claustrum `ck` CLI on Windows. Previously it could report "Neither OpenCode nor Pi was detected" when they were installed through npm or Bun, installed as OpenCode Desktop, or installed but not yet run.
- **Vault enrollment on Windows.** The Claustrum client is updated to 0.9.0, and the shared auth library to 0.15.0. Both store private files so only your Windows account can read them. Mac and Linux behave as before, and existing enrollments keep working with no re-enrollment.
- **OpenCode 2 retries.** A request that retried after an expired login no longer fails with "Native Prime was not completed".
- **File locking.** A timing gap in the shared lock code could let two writers hold the same file lock at once. That is fixed (`@cortexkit/common-auth` 0.15.0), and session routing, vault enrollment and quota saves also check they still hold their lock before writing. Before, two OpenCode processes saving at the same moment could drop a session's account pin, moving that session to another account and rebuilding its prompt cache.

## Upgrading

From 2.0.0, update the plugin and restart OpenCode or Pi. No setup step is needed.

From 1.x, follow the 2.0.0 upgrade steps: quit every OpenCode, LiteCode and Pi process, then run `bunx @cortexkit/opencode-anthropic-auth@2.0.1 setup`.

## For integrators

`@cortexkit/anthropic-auth-core` is now an internal package of the OpenCode and Pi plugins. Its public, stable API is the identity, header, billing and signing functions listed in its README; anything else may change in any release. This release removes the 1.x scoped vault-custody modules, the 1.x sidecar account-file loaders and writers with `FallbackAccountManager`, and the sidecar routing-mode writer from Core's exports.
